# Representation Search: the encoding as a searched parameter

**Status:** proposal (track spec, not started). **Filed:** 2026-10-07. **Depends on:**
the existing IR pipeline and gate harness (both built); **gated on #30 having produced
a first candidate batch** — see "Sequencing" below, and the reason is DEC-054, not
timidity.

> **What this is.** A second research track, complementary to axiom discovery. Axiom
> discovery searches for a structure-preserving map **φ** (a *technique*) and certifies
> transfer results by kernel. This track searches for a **representation** — the
> encoder itself — and scores it by whether a *fixed, capacity-bounded* model learns
> compositionally from it. Both are "search over constructions with a fixed external
> judge"; they differ in what is searched (φ vs the encoding) and what is judged
> (kernel-checked transfer vs kernel-checked faithfulness **plus** a held-out
> generalization score).

## 1. Why this is not just "redo the IR experiments"

Maith already tested *one* representation (the hand-designed semantic IR) against raw
BPE and AST, and the result is on record: the IR encodes semantics (DEC-025, 62-pp
probe gap) but does **not** beat size-matched BPE under prediction metrics (DEC-027),
the prediction-era runs were invalidated (DEC-031), and the clean re-runs are
ambiguous (DEC-034/035). A fair reading is *"this one candidate representation did not
show advantage on those metrics."*

That is a statement about **one point in representation space**, evaluated on
**prediction/retrieval metrics**. It is not a statement about the space, and not a
statement about the metric this track uses. Two things change here:

1. **The representation becomes a searched variable**, not a hand-designed artifact —
   a grammar over encodings, explored by search.
2. **The metric becomes compositional generalization of a bounded model** — the
   capability the central hypothesis actually cares about, and the one Maith never
   measured. Perplexity and retrieval were the wrong lens (H11 says so).

The honest prior stays on the table: the closest single-point result was null. This
track exists to test whether the *space*, searched under the right objective, contains
better points — and it is designed to disprove that.

## 2. The well-posedness constraint (why a fixed theory is required)

A representation-search engine is only well-posed if its objective is **external and
fixed**. Without that, the search is gameable: for any finite dataset a lookup-table
encoding achieves 100% accuracy, and a representation that makes ∧ trivial while
breaking ∨ is "different," not "better."

So three things are frozen before any search runs, and they are not search parameters:

- **Base theory `T`** — the semantics the encoding must preserve. Start with
  **propositional logic** (truth-table semantics, decidable, exhaustively checkable)
  and reuse `PleaNP.Circuits`/Lean for circuit-shaped content as the track matures.
  The kernel (`lake build`) remains the sole oracle, unchanged from every prior doc.
- **Task distribution `D`** — entailment `Γ ⊨ φ` over a fixed signature, generated by
  construction with depth/composition/negation/renaming metadata. **Free** (it is code).
- **Invariance class** — what the encoding must preserve: equivalence classes of
  formulas under truth-table semantics; derivability. Fixed by `T`.

A candidate is a pair `(enc_R, faithfulness_claim)`. It is admissible only if
`enc_R` is **provably faithful to `T`** (below). Faithfulness is not scored; it is a
gate.

## 3. The fixed method (what stays constant while content varies)

This is the discipline that keeps the program well-posed, and it is the same
propose/validate split DEC-039 already established for the axiom track:

| Role | Owner | Frozen? |
|---|---|---|
| Faithfulness checker (is `enc_R` equivalent to `T`?) | **deterministic** (kernel / truth tables) | frozen |
| Corpus/task generator (`D`) | **deterministic** | frozen (hashed) |
| Benchmark harness (model, capacity, seeds) | **deterministic** | frozen (hashed) |
| Candidate encodings / mutations | **AI proposes** | the searched content |
| Accept/reject decision | **never AI** — the harness decides | frozen |

The benchmark model is deliberately **small and capacity-bounded** (reuse the
Qwen2.5-Coder-0.5B base already pinned, or smaller), for the anti-degeneracy reasons in
§5. Novelty is measured against a held-out corpus and the kernel, **never** against the
engine's own account of itself.

## 4. The encoding grammar (the searched parameter)

The representation is a **linearization of a formula's parse tree**, so the search is
over a grammar of linearization decisions. Every candidate is an algorithmic encoder —
not a lookup table, not a per-item map — so no candidate can smuggle content.

Initial grammar (deliberately boring; the search discovers structure):

- **Node rendering** — how an operator is spelled (canonical names, positional,
  arity-prefixed, type-tagged). The existing `per_operator` mode is one point here.
- **Child order** — fixed source order, canonical sort, or a learned/encoded priority.
- **Scope/binder marking** — explicit delimiters vs positional counting (the existing
  `FVAR_N`/`BVAR_N` scheme is one point here).
- **Grouping** — how subtree boundaries are marked (parentheses stream vs boundary
  tokens vs RPN-style postfix).
- **Redundancy policy** — whether semantically-loaded extra tokens are permitted
  (H11 says canonicalization removes predictability; a candidate may *add* it back).

A candidate encoder `enc_R` maps a parse tree to a token sequence. Faithfulness means:
`enc_R` is injective on `D` up to the invariance class — i.e. two formulas with
different truth-table behavior never collide. For propositional logic this is
**exhaustively checkable on a bounded domain** and, for the grammar above, provable in
general (the encoder is a structural recursion).

## 5. Anti-degeneracy conditions (all four required)

Drop any one and the search is a way to manufacture flattering results:

1. **Bounded model capacity and compute** — a small fixed model, fixed token budget,
   fixed steps. Memorization-friendly encodings cannot win by brute force.
2. **Compositional / OOD test** — withhold entire parse-tree compositions from training
   and test on them; also depth-extrapolate (train d≤5, test d=6…20). Random splits are
   insufficient; the split is **structure-based**.
3. **Faithfulness gate** — no candidate may trade semantics for score. Checked by the
   kernel (or exhaustive truth-table equivalence on `D`).
4. **Fixed task distribution `D`** — the search cannot pick an easier task. `D` is
   generated, hashed, and versioned before training.

## 6. Metrics and the primary endpoint

- **Primary:** held-out compositional accuracy and depth-extrapolation accuracy of the
  bounded model under `enc_R`, vs the fixed baselines.
- **Baselines:** raw source/BPE, the existing semantic IR, majority class, a
  parse-tree-statistics logistic regression, and a length-only heuristic.
- **Uncertainty:** the model must also expose an uncertainty signal; report
  **selective accuracy @ coverage {0.5, 0.8}** and **risk–coverage AUC**, so this track
  stays compatible with the learned-validity-estimator idea (an encoding that makes a
  bounded model *well-calibrated* is as interesting as one that makes it accurate).

**Falsification (two independent ways to fail).** Accept H0 — no representation
advantage exists — if the best searched encoding's held-out compositional accuracy is
≤ the best fixed baseline within the CI, **and/or** its uncertainty AUROC is ≤ the
length-only heuristic. If either holds on the full grid, the null is reported as the
result, with the same weight Maith gives every negative (the DEC-010 precedent).

**Anti-gaming, stated as a rule.** A candidate that improves in-distribution accuracy
but not compositional accuracy has learned the *task*, not the *representation's
structure* — it does not count. Compositional/OOD accuracy is the only primary.

## 7. Sequencing — do not start ahead of results

**This track does not start until #30 has produced a first candidate batch.** The reason
is recorded in Maith's own DEC-054: building infrastructure while the active track has
no first result "would repeat the infrastructure-ahead-of-results mistake this project
has already made once." Concretely, the order is:

1. **#30 runs** (unblocked by DEC-057; waits only on authored candidate φ's) — the
   axiom track gets its first candidate batch and its first real gate outcomes.
2. **Only then** does the representation-search harness get built, as a **new generator
   bolted onto the substrate #30 exercised** — reuse the corpus, the round-trip
   validator, the hashed splits, and the gate discipline. Nothing here is built from
   scratch.
3. The Jev/Clef zero-shot validity measurements (independent, in `/tmp` — see the
   conversation record) are a natural first fixed benchmark entry for the bounded
   model, but they are **not** part of this track and do not gate it.

## 9. Explicitly out of scope: the quantum / judgment layer

No qubit or judgment-algebra layer is part of this track, and its **precondition does
not exist**: there are no composable judgment objects `J = (claim, verdict, confidence,
evidence, dependencies)` whose *composition order* changes the outcome. Maith's gates
are order-independent (a homomorphism holds or it doesn't; a proof checks or it
doesn't), so there is no interference signature for a quantum-like representation to
explain. The quantum layer enters — if ever — only after (a) a judgment algebra exists
and (b) an order/context effect is **measured** that classical probability cannot
capture. Until then it is off the board. (When it does enter, it is exact classical
statevector simulation on free infra — real QPU time is not available at study scale,
and at 2–4 qubits adds interpretation, never capability.)

## 10. Free-infra budget

Consistent with the rest of Maith, which already runs on a consumer **M4 / 16GB via
MPS** with free dependencies (`torch`, `transformers`, `numpy`, `sklearn`) and the
community Mathlib olean cache:

- Corpus generation: **free** (code).
- Faithfulness checking: **free** (kernel / truth tables).
- Bounded-model training: **laptop-scale** (0.5B params, short runs) — same envelope as
  existing runs.
- No paid service, no GPU rental, no QPU time.

The search loop is the only new compute; it is bounded by the same 30-minute-run
discipline the rest of the portfolio uses, and each candidate's score is a single
short training run plus an eval.

## 11. Prior art to cite before building (not novelty claims)

Neural architecture search; program synthesis / symbolic regression; automated feature
engineering; formal-methods faithfulness proofs; identifiability in representation
learning. Maith's contribution, if any, is the **integration** — search over encodings
under a kernel faithfulness constraint, scored by compositional generalization — not
the pieces. Per the standing rule, nothing here authorizes a novelty claim.
